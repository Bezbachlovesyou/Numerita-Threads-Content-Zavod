# Наблюдаемые квоты и снижение нагрузки — 27.10.2026

## Что проверено

В ответе GET /accounts/{accountId}/health: HTTP 200, status healthy, token valid,
canPost и canFetchAnalytics true, нет missingRequired/ issues. Этот health проверяет
подключение, а не отсутствие всех санкций или допуск аккаунта к рекомендациям Meta.
Заголовки фактического ответа: лимит 60/мин, остаток 59. Это моментальный снимок.
В проверенных логах 429 пришли на GET /inbox/comments/{postId}, а не на отправку ответа.
Одного HTTP-статуса без тела и заголовков недостаточно для определения источника.

Источники:
- https://docs.zernio.com/guides/rate-limits
- https://docs.zernio.com/guides/error-handling
- https://docs.zernio.com/accounts/get-account-health

## Реализация

- Общий для данного клиента интервал API не менее 3 секунд (до 20 стартов запросов/мин).
  Пауза сохраняется в БД, используется новым запуском процесса, действует также на
  аналитику и публикации через этот клиент. Дневные бизнес-лимиты не повышаются.
- Заголовки X-RateLimit-* читаются на каждом ответе. При достижении резерва около
  20% оставляем запросы до указанного reset; для analytics учитываем отдельное окно.
- 429 сохраняет паузу; работает предыдущий экспоненциальный backoff автоответов.
- За один проход читаем до шести веток, прежде всего дольше не проверенные. Старые
  дискуссии сохраняются в очередности. Пагинация выбранной ветки по-прежнему до 10
  страниц/500 элементов, сообщения архивируются прежним кодом. Неразобранные ответы
  не удаляются из-за достижения лимита прохода. При большой очереди задержка может вырасти.
- Сохраняются последние квоты general/analytics, последний 429 и его известный тип,
  дневное число API-запросов/чтений/ответов/429. Без токенов, URL с параметрами или
  текста комментариев. Счётчики начинают накапливаться после этого выпуска.
- /safety у админа показывает снимки с временем; не делает новых API-запросов.
  Эти числа не называем процентом вероятности блокировки.

Лимит данного worker не ограничивает другой сервис или пользователя Zernio с тем же
общим бюджетом. Резерв заголовков помогает, но не гарантирует нулевое число 429 при
чужой одновременной нагрузке. Другие проекты Railway не менялись, ключи не ротировались
ради обхода ограничений, платные тарифы не подключались.

## Что не установлено

Прямой остаток квоты ответов/постов Meta через этот ответ Zernio не получен. Локальные
счётчики не заменяют его. Закрытый статус рекомендаций Meta не прочитан. Причинная связь
между этими 429 и снижением просмотров/подписок не доказана. Для оценки результата
сравнивать частоту 429 и задержку ответов после выпуска; охваты сравнивать на сопоставимом
контенте и возрасте постов. Не заявлять успех только по отсутствию уведомлений.

Проверки: полный набор 74 теста на изолированной PostgreSQL, SQLite-варианты,
компиляция. Новые проверки используют фейковое время и API; намеренно достигать реального
лимита не требуется. Наблюдение после deploy фиксируется отдельно.
