## Мониторинг

performance.collect запускается каждые30минут, не более20 запросов за проход. Целевые окна возраста:1–1,5ч;24–26ч;72–75ч. Старому посту нельзя приписать его сегодняшний счётчик как исторические24ч. Если последний замер провайдера старше окна, он не участвует в сравнении. Пропущенные окна остаются пропущенными; старые показатели искусственно не восстанавливаются. Данные хранятся в существующем KV, без миграции/перезаписи личных переписок.

Сохраняются реальные доступные likes/comments/views/impressions/shares/reposts, источник, момент запроса, возраст поста, время последнего обновления провайдера и ссылка. Ноль отличается от отсутствующих данных. Views не заменяются impressions. В multi-platform ответе используется только часть Threads. Comments — счётчик платформы, который может включать собственные ответы аккаунта; число уникальных людей/продаж из него не выводится. Локальная таблица обработанных/пропущенных комментариев больше не является источником ранжирования форматов.

Команда владельца /performance показывает по последним15 постам текст, рубрику, UTC-время публикации и доступные счётчики; ещё нет данных — это явно написано. Ежедневный отчёт самоулучшения использует сопоставимые24–26ч наблюдения. Код уже сохраняет текст, тему, рубрику, оформление и время; на их основе действующий оптимизатор корректирует веса рубрик, временных окон и оформления. Сопоставимые наблюдения применяются также к повтору слабого поста и сравнению ссылок.

Очки — эвристика comments+0,2×likes. Просмотры отображаются, но не добавляются к очкам: охваты не равны положительной реакции. Не использовать разреженные показатели просмотров как знаменатель для смешанного рейтинга, пока их доступность/определение не подтверждены. Лайки и комментарии в отчёте видны отдельно. Минимум3 сопоставимых поста — лишь защитный порог эвристики, не статистическое доказательство. Часы/темы могут быть связаны с разными аудиториями; вывод «время вызвало рост» без эксперимента запрещён. Охват, продажи, маржа и качество разговора — разные цели. Платёжная атрибуция этим изменением не добавлена.

Новых LLM-запросов, покупок подписок или увеличения бюджета нет. Если тариф не включает Analytics, отчёт указывает недоступность; сам ничего не покупает. Поисковый просмотр публичного аккаунта не заменяет собственные счётчики.

## Проверка и выпуск

Тесты с фейковыми Telegram/Zernio: приоритет с точной картинкой; подтверждение Threads; защита от повторного POST после обрыва; запрет публикации без картинки; реальные платформенные комментарии вместо локальной очереди; ноль/пропуск; возраст/свежесть; отдельная часть Threads. Запуск на SQLite и выделенной локальной PostgreSQL. Компиляция zavod/*.py. Результат выкладки и фактический URL поста проверяются отдельно: GitHub/зелёный deploy сами по себе не являются квитанцией публикации.
